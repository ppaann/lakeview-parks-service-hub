# Project record: City of Lakeview Parks & Recreation Resident Service Hub

> Independent, self-directed portfolio demo for a fictional city. Not affiliated with any real city or government agency.

**Last updated:** Sun Nov 8, 2026

## What it is and who it serves

A Dynamics 365 Customer Service configuration for a fictional city's Parks & Recreation department. Residents contact staff about:

- facility rentals
- registration problems
- refunds
- complaints
- asset-maintenance issues

Staff log cases, route them to queues, and meet a response-time SLA. A small asset-maintenance extension adds basic EAM-style asset tracking (not a full EAM or QAlert implementation).

**Audience:** hiring managers for local-government QA / business analyst roles, especially a King County IT QA Engineer role.

## Defect candidates (to log in ADO on Fri)

- **DEF-01 (AC-05.1):** CSV import accepts a row with a blank **Asset ID** (Business required not enforced server-side; see R-13).
- **DEF-02 (AC-05.1):** CSV import accepts a row with a blank **Asset Name** (primary column).
- **DEF-03 (AC-05.3, higher severity):** CSV import accepts rows with invalid choice values and the wizard **adds them as new choice options** ("Broken" now in Condition, "Swing Set" now in Asset Type), reporting the rows as **Success**. A data import changed the schema, and the extra options would be exported with the solution.
- **Cleanup after logging (before solution export):** delete the 4 bad asset records, then remove the "Broken" and "Swing Set" options (Learn: removing a used option invalidates existing records, so delete the records first).
- **DEF-04 (cosmetic, low):** Parks Asset form shows each field in its own "New Section" header, with Owner first. Tidy into one "Asset details" section; good low-priority triage example.
- **DEF-05 (observation, to verify):** On SLA-TEST 01, the case field **First Response SLA Status** stays **In Progress** while its SLA KPI instance is **Noncompliant**. Possibly expected (the case status fields may belong to the older SLA model, while enhanced SLAs track status on KPI instances), but unverified. Impact: reports (US-08) must use KPI instance status, not this case field. Check Microsoft Learn before logging as a defect.
- **DEF-06 (cosmetic, low):** Case form shows generic labels "New Tab", "New Section", "New SG control …", and First Response Sent appears twice. Rename to SLA labels and remove the duplicate.
- **DEF-07 (observation, low/UX):** For an unauthorized user, the secured **date** column Birthday renders as an **empty** box with a lock, while the secured text column Payment Notes renders "******". Learn describes "********". An empty date can be misread as "no birthday on file". Value is hidden either way (no data exposure).
- Possible fixes to evaluate in triage: Entity-scope business rule on Parks Asset (server-side error, as observed for Cases); a pre-import CSV validation step; documenting a platform limitation.

So Category and Asset requirements can be bypassed through the API. Confirms the General Intake fallback (AC-02.2) and means AC-04.4 needs server-side enforcement. Learn's business rule page says Entity scope = "forms and server" but its FAQ also says business rules "run on clients" (conflict); Set Business Required is form-only. Plan: Entity-scope rule with **Show error message**, then test a Web API create on Fri; log the result either way.
- **Note (Nov 4):** Workspace case form = **Case for Multisession experience** for both new and existing cases (observed). Command bar shows **Save & Route**: check on Wed/Thu whether routing runs on plain Save or only Save & Route (R-07). A Copilot **Case summary** card is visible on sample cases (input for the AI-testing stretch; licensing still to verify).
- **R-14 (Nov 4):** The import job's Created On shows **11/5 12:4x** although it ran at ~4:45 pm Pacific on Nov 4, so the Dynamics **user time zone is probably UTC**, not Pacific. This affects how dates display and how SLA deadlines look in tests. **Confirmed and fixed for Pan's user (Nov 4):** Personalization Settings showed (GMT) Coordinated Universal Time; changed to (GMT-08:00) Pacific Time (private notes s1-25, s1-26). It's a per-user setting: set it for each test identity on Thu, and check the SLA business-hours calendar's own time zone.
- **R-07 update (Nov 6, Microsoft Learn, May 2026):** Basic routing rulesets: one active ruleset at a time; rule items evaluated top to bottom, first match wins. Cases created in the **UI** have **Route Case = No** by default, so a plain Save doesn't route; **Save & Route** or **Apply Routing Rule** does. Cases created **programmatically** (Web API) have **Route Case = Yes** by default and route **on create**. Not documented: what happens when no rule matches, and whether routing changes the owner. Design: add an explicit catch-all rule item last for General Intake; test owner/queue item behavior. Rulesets are solution-aware, but their queue mappings aren't: document queue setup in the repo.
- **R-15 (Nov 6, observed + Learn):** Save & Route on CAS-01003 (Complaint) created **no queue item** and **no background job**. Unified routing is **enabled** in this trial (toggle = Yes). Learn (Oct 2026): "After you enable unified routing, the active basic routing rule won't route records until you configure intake rules" mapped to it. Fix: add Case under Record routing with an intake rule mapped to Lakeview Case Routing. Learn doesn't document the selector label, the no-match behavior or the trigger, so verify by test.
- **R-16 (Nov 7, Microsoft Learn):** Security testing dependencies. (1) Every test user needs a **license** (assign licenses, Sep 2025); the Customer Service trial FAQ (Feb 2026) says add users "up to the trial license limit" but gives no number, so check available trial seats in the Microsoft 365 admin center first. **Checked Nov 7:** Dynamics 365 Customer Service Enterprise vTrial, **1 of 10,000 assigned** (subscription Oct 29, 2026), so licenses aren't a constraint.
